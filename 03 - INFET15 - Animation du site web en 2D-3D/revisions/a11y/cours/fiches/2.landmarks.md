# Régions repères (`landmarks`)

## Kesako ? 

Tout le contenu perceptible d’une page doit se trouver réparti dans ses **régions repères**. En anglais : `landmarks`. 

Chaque région repère a un **rôle sémantiquement** significatif. C'est l'un des moyens les plus efficaces de garantir que les utilisateurs de technologies d'assistance ne manqueront pas les informations pertinentes pour leurs besoins.

Les lecteurs d'écran exploitent les balises de structure de la page pour **fournir une navigation au clavier** vers des sections importantes d'une page, notamment pour profiter d'un **accès rapide** au clavier.

Il y a **8 régions repères** (landmarks) définies par la spécification ARIA : 
- `banner`
- `navigation`
- `main`
- `region`
- `complementary`
- `form`
- `contentinfo`
- `search`

## Exemple sur une page 

Cliquer sur le bouton `Show Landmarks` [de cette page](https://www.w3.org/WAI/ARIA/apg/patterns/landmarks/examples/general-principles.html)

## Comment définir les landmarks sur une page HTML ?

On utilise en priorité les **balises HTML** fournissant la sémantique correspondante. Cela crée automatiquement une région repère sur la page.

Parfois, il faut ajouter un attribut complémentaire afin de définir la région.

Pour observer les landmarks d'une page dans les DevTools Chrome : `HTML` > `Accessibilité`. 

| Région repère | Balise                         | Explications                                                                                                                                                                                                                                                                                                                      |
| ------------- | ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `banner`        | `<header>`                       | Le repère de bannière est utilisé pour identifier l'en-tête d'une page Web, qui contient généralement le logo du site, la navigation et la zone de recherche. Lorsque l'élément `<header>` n'est pas utilisé comme enfant de l'élément `<main>` ou d'un autre élément de section, il se voit automatiquement attribuer le rôle de bannière.           |
| `navigation`    | `<nav>`                          | Le repère de navigation est utilisé pour identifier un ensemble de liens qui aident les utilisateurs à naviguer sur la page Web ou sur des pages Web connexes. Cela peut inclure des éléments tels que la navigation latérale, la navigation principale du site ou un ensemble de liens connexes dans le pied de page de la page. |
| `main`          | `<main>`                         | Contenu principal de notre page. Il est important de noter qu'une page ne peut avoir qu'un seul élément `<main>`.                                                                                           |
| `contentinfo`   | `<footer>`                       | Le repère d'informations sur le contenu est utilisé pour identifier le pied de page d'une page Web, qui peut contenir des informations sur les droits d'auteur, des liens vers la politique de confidentialité, ou d'autres informations liées au contenu.                                                                        |
| `region`        | `<section aria-labelledby="ID">` | Section du document vers laquelle il serait intéressant pour un utilisateur de pouvoir naviguer directement. L'ajout d'un attribut `aria-labelledby` et un ID spécifique d'un élément (généralement un titre contenant la description de la section), permet de créer la région.                                                                                                                                                      |
| `complementary` | `<aside aria-labelledby="ID">`   | Élément complémentaire, souvent utilisé pour regrouper du contenu connexe mais qui n'est pas directement lié au contenu principal de la page. L'ajout d'un attribut `aria-labelledby` et un ID spécifique d'un élément (généralement un titre contenant la description de la section), permet de créer la région.                                                 |
| `form`          | `<form aria-labelledby="ID">`    |  L'ajout d'un attribut `aria-labelledby` et un ID spécifique d'un élément (généralement un titre contenant la description de la section), permet de créer la région. |
| `search`        | `<form role="search">`           | Le rôle de recherche est utilisé pour regrouper un ensemble d'éléments liés qui fournissent ensemble un moyen de rechercher sur le site Web. La manière la plus courante d'utiliser ce rôle est à travers un formulaire. Il faut alors préciser le `role="search"` de ce formulaire. À noter, il existe un élément sémantique `<search>` mais celui-ci n'est pas encore en 2024 tout à fait supporté par l'ensemble des navigateurs. |

[Source](https://developer.mozilla.org/en-US/blog/aria-accessibility-html-landmark-roles/)

## ARIA `role` et rétrocompatibilité

Certains navigateurs (vieux ou non mis à jour) ne supportent pas les balises HTML récentes (`<main>`, `<section>`, etc...) qui sont alors interprétées comme des `<div>` ne présentant pas de sémantique. 

Pour assurer une rétrocompatibilité avec ces navigateurs, on peut utiliser l'attribut `role` sur nos éléments HTML pour s'assurer la création d'un landmark. Il faut alors avoir conscience que cela crée une redondance sémantique pour les navigateurs récents, que la [documentation MDN](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Roles/landmark_role) suggère d'éviter.

De manière générale, les ARIA `role` permettent d'ajouter une sémantique à des éléments lorsqu'il n'existe aucun élément HTML correspondant à la sémantique désirée. Par exemple : `role="tab"`, car il n'y a pas de balise `<tab>` en HTML. [Pour en savoir plus](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Roles).

La liste des `role` pour définir des `landmarks` est donnée dans l'exemple à titre indicatif.

## Exemple

```html
<header role="banner"> <!-- role facultatif (rétro-compatibilité) -->
  
  <nav role="navigation"> <!-- role facultatif (rétro-compatibilité) -->
    <ul>
      <li><a href="#">Lien 1</a></li>
      <li><a href="#">Lien 2</a></li>
    </ul>
  </nav>

  <form role="search"> <!-- rôle nécessaire : les navigateurs ne supportent pas tous l'élément <search> -->
    <!-- search input -->
  </form>

</header>

<main role="main"> <!-- role facultatif (rétro-compatibilité) -->
  <!-- main content of the page -->

  <h1>Main title</h1>
  
  <section labelled-by="fiesta" role="region"> <!-- role facultatif (rétro-compatibilité) -->
    <h2 id="fiesta">La fête de la musique</h2>
    <p>lorem ipsum</p>
  </section>
  
  <section labelled-by="playa" role="region"> <!-- role facultatif : pour la rétro-compatibilité -->
    <h2 id="playa">La plage des vacances</h2>
    <p>lorem ipsum collat</p>
  </section>

</main>

<aside labelled-by="subscribe-newsletter" role="complementary"> <!-- role facultatif : pour la rétro-compatibilité -->
  <h3 id="subscribe-newsletter">S'inscrire à la newsletter</h3>

  <form aria-labelledby="subscribe-newsletter" role="form"> <!-- role facultatif (rétro-compatibilité) -->
    <!-- form content -->
  </form>
</aside>

<footer role="contentinfo"> <!-- role facultatif (rétro-compatibilité) -->
  <!-- footer content -->
</footer>
```

## Les liens d'évitement (`skip nav`, `bypass blocks`)


Un lien d'évitement est une technique qui permet aux utilisateurs de sauter rapidement le contenu répétitif ou les éléments de navigation pour accéder directement au contenu principal d'une page. Cela aide particulièrement les personnes utilisant des lecteurs d'écran ou d'autres technologies d'assistance à naviguer plus efficacement sur un site web.

```html
<!-- Exemple -->
<header id="skiptocontent" class="sr-only">
  <a href="#maincontent">Skip to main content</a>
</header>

<!-- Généralement, on donne le focus à l'élément et on l'affiche lorsqu'il est atteint au clavier. -->
```

Exemple de sites utilisant un lien d'évitement : 
- [a11yproject](https://www.a11yproject.com/posts/skip-nav-links/)
- [WCAG20](https://www.w3.org/TR/UNDERSTANDING-WCAG20/navigation-mechanisms-skip.html)


## Checklist

- [ ] L’ensemble des éléments de la page doit être réparti dans des zones de repère.
- [ ] Les balises de premier niveau sont `<header>`, `<main>`, `<aside>`, `<footer>`.
- [ ] Un seul `<main>` autorisé.
- [ ] Plusieurs `<header>` et `<footer>` sont autorisés, mais avec un label unique (`aria-labelledby` > `aria-label`).
- [ ] Utiliser si nécessaire un lien d'évitement pour accéder au contenu rapidement.
