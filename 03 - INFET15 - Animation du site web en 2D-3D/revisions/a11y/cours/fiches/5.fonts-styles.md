# Polices et styles

## Ne pas utiliser de balises ou d’attributs liés à la présentation

### Les balises dépréciées

Les éléments `basefont`, `blink`, `center`, `font`, `marquee`, `s`, `strike`, `tt` et `big` sont interdits.

### Les attributs dépréciés

Les attributs `align`,  `alink`,  `background`,  `bgcolor`,  `border`,  `cellpadding`,  `cellspacing`, `char`, `charoff`,  `clear`,  `compact`,  `color`,  `frameborder`,  `hspace` , `link`,  `marginheight`,  `marginwidth`,  `text`,  `valign`,  `vlink`,  `vspace`,  `size` sont interdits.

Note : les attributs `width` et `height` utilisés sur d’autres éléments que les balises `<img>`,  `<object>`,  `<embed>`,  `<canvas>`  et `<svg>` sont également interdits.

### Les balises pour créer des espaces, ou de la mise en forme

Les balises de passage à la ligne et de paragraphe pour créer de l’espace

Exemple avec la balise `<br>` 

```html
<p>
paragraphes d'un bloc de texte simulés
<br>
<br>
à l'aide de plusieurs balises <br>
</p>
```

Exemple avec la balise `<p>`

```html
<p></p>
<p>paragraphe d'un bloc de texte</p>
<p>&nbsp;</p>
```

Exemple avec les espaces insécables &nbsp;

```html
<p>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Paragraphe avec une indentation artificielle</p>
```

## Gestion du zoom texte 200% et du zoom navigateur 200%

### Zoom Navigateur

Il s’obtient en faisant `ctrl`+`+`, `ctrl`+`-` ou `ctrl`+`0`.

### Zoom texte seulement (facultatif)

Certains navigateurs permettent d’agrandir uniquement la taille du texte. 
C’est le cas de Firefox par exemple.
Pour régler l’affichage de Firefox en zoom texte seulement
Menu Affichage > Zoom > Zoom texte seulement.

Quand ce cas d’usage n’a pas été envisagé, on peut avoir :

- des textes qui sont coupés dans des colonnes trop étroites
- des textes qui débordent des blocs
- des textes coupés dans des blocs trop étroits.

### Du bon usage des unités relatives pour gérer le zoom texte

#### Définir les textes en em

L’utilisation d’unités relatives pour le texte telles que les `em`, ou les `rem` permet de résoudre quelques problèmes. 
En effet, si le texte peut être zoomé, alors les containers doivent aussi suivre l’augmentation de la taille pour ne pas tronquer ou faire se chevaucher le texte.

**Différence entre em et rem**

Le **rem** rend une taille proportionnelle par rapport à la taille du texte à la racine du document.

Le **em** rend une taille proportionnelle par rapport à la taille de l'élément parent dans lequel il est contenu.

→ **Privilégier le rem** (mais à défaut, le em, c’est bien aussi)

### Utiliser des hauteurs minimales pour la hauteur des blocs

Pour gérer des blocs qui ont des hauteurs fixes, dont les éléments vont déborder si on agrandit le texte ou si on augmente les espacements entre les textes.

Définir une hauteur minimale au lieu d’une hauteur fixe.

```css
.bloc {
	min-height: 28.125rem; 
}
```

### Gestion des media-queries (ou points de rupture) en unités relatives

Les media-queries permettent de détecter la taille de l’écran d’affichage, et d’imposer un style selon le format d’affichage 

Quand la taille de police est agrandie, les textes peuvent se retrouver entassés et difficiles à gérer.

L’une des solutions est de faire en sorte que quand la taille de police est agrandie, on passe à un affichage tablette, où on a gardé toutes les fonctionnalités.

Les points de rupture classiques :

- Mobile → SM : 576 pixels
- Tablette → MD : 768 pixels
- Ordinateur → LG : 992 pixels
- Grand écran → XL : 1248 pixels

Mettre ses media-queries en unités relatives permet de prendre en compte l’agrandissement de la taille de police par défaut.

Sachant que par défaut 1 em = 16px :

- Mobile → SM : 576 pixels → 36 em
- Tablette → MD : 768 pixels → 48 em
- Ordinateur → LG : 992 pixels → 62 em
- Grand écran → XL : 1248 pixels → 78 em

```css
@media (max-width: 36em) {
    html {
      background: yellow;
    }
}

@media (max-width: 48em) {
    html {
      background: orange;
    }
}

@media (max-width: 62em) {
    html {
      background: red;
    }
}

@media (max-width: 78em) {
    html {
      background: purple;
    }
}
```

Source [https://zellwk.com/blog/media-query-units/](https://zellwk.com/blog/media-query-units/)

## Laisser l’utilisateur personnaliser son affichage textuel

### Garantir la lisibilité en cas de changement des espacements de lettres, de mots, de hauteur de ligne

Dans le cas où un utilisateur a mis en place une police par défaut avec un interlignage, un espace entre les mots, les caractères différents, peut-il encore lire l’information ?  

```css
* {
    line-height: 1.5!important;
    letter-spacing:.12em!important;
    word-spacing: .16em !important;
}

p {
    margin-bottom: 2em!important;
}
```

## Les informations sont-elles visuellement perceptibles pour ceux qui voient ?

### Distinguer les éléments de leur arrière-plan

- Dans chaque page web, les couleurs utilisées dans les [composants d’interface](https://www.numerique.gouv.fr/publications/rgaa-accessibilite/methode-rgaa/glossaire/#composant-d-interface) ou les éléments graphiques porteurs d’informations sont-elles suffisamment contrastées (hors cas particuliers) ?
- Dans chaque page web, le [contraste](https://www.numerique.gouv.fr/publications/rgaa-accessibilite/methode-rgaa/glossaire/#contraste) entre la couleur du texte et la couleur de son arrière-plan est-il suffisamment élevé (hors cas particuliers) ?

Les couleurs doivent être suffisamment contrastées pour faciliter la lecture

### Des informations qui ne sont pas données par la couleur, la taille, la position ou la forme

- Dans chaque page web, l’information ne doit pas être donnée [par la forme, taille ou position](https://www.numerique.gouv.fr/publications/rgaa-accessibilite/methode-rgaa/glossaire/#indication-donnee-par-la-forme-la-taille-ou-la-position) uniquement. Cette règle est-elle implémentée de façon pertinente ?
- Dans chaque page web, l’[information](https://www.numerique.gouv.fr/publications/rgaa-accessibilite/methode-rgaa/glossaire/#information-donnee-par-la-couleur) ne doit pas être donnée uniquement par la couleur. Cette règle est-elle respectée ?

### Une couleur d’arrière-plan définie par défaut

- Dans chaque page web, les déclarations CSS de couleurs de fond d’élément et de police sont-elles correctement utilisées ?

### Les liens identifiables facilement

Les liens doivent pouvoir être identifiés visuellement lorsqu’ils se trouvent dans un bloc de texte

- Dans chaque page web, chaque [lien dont la nature n’est pas évidente](https://www.numerique.gouv.fr/publications/rgaa-accessibilite/methode-rgaa/glossaire/#lien-dont-la-nature-n-est-pas-evidente) est-il visible par rapport au texte environnant ?

### Les images

Une image avec un texte sur un arrière-plan peut-elle être remplacée par un texte stylisé ?

- Chaque [image texte](https://www.numerique.gouv.fr/publications/rgaa-accessibilite/methode-rgaa/glossaire/#image-texte) [porteuse d’information](https://www.numerique.gouv.fr/publications/rgaa-accessibilite/methode-rgaa/glossaire/#image-porteuse-d-information), en l’absence d’un [mécanisme de remplacement](https://www.numerique.gouv.fr/publications/rgaa-accessibilite/methode-rgaa/glossaire/#mecanisme-de-remplacement), doit si possible être remplacée par du [texte stylé](https://www.numerique.gouv.fr/publications/rgaa-accessibilite/methode-rgaa/glossaire/#texte-style). Cette règle est-elle respectée (hors cas particuliers) ?

### L’information reste-t-elle présente lorsque l’on désactive les styles ?

Lorsque les informations sont portées par la feuille de style, celles-ci disparaissent lorsqu’elle est désactivée.

On vérifie ici que tous les éléments stylisés avec des images gérées en feuille de style ont une équivalence textuelle.

Exemple : bouton image.

### L’information reste-t-elle [compréhensible](https://www.numerique.gouv.fr/publications/rgaa-accessibilite/methode-rgaa/glossaire/#comprehensible-ordre-de-lecture) lorsque les [feuilles de styles](https://www.numerique.gouv.fr/publications/rgaa-accessibilite/methode-rgaa/glossaire/#feuille-de-style) sont désactivées ?

On vérifie ici que l’ensemble des éléments de la page sont compréhensibles.

Exemple : un ordre des éléments qui positionnait le dernier bloc en tout premier visuellement.

Sans style, il se retrouve dans une position qui n’est pas compréhensible.
