# `ARIA` et composants d'interface riche

`ARIA` (_Accessible Rich Internet Applications_) sert à donner des informations aux technologies d'assistance. Ces attributs agissent **uniquement** sur la sémantique des éléments (pour donner un nom à un élément, préciser un état, etc...)

## Règle n°1 d'ARIA : ne pas utiliser ARIA

**On utilise les attributs `ARIA` lorsqu'on ne peut pas faire autrement avec la sémantique HTML de base.**

## L'attribut `role`

Sert à changer la sémantique de base d'un élément. Il ne change PAS le comportement ni l'affichage de cet élément.

Exemples :
- `<button role="link">` sera restitué comme un lien par les lecteurs d'écran. Visuellement, il ressemblera toujours à un bouton dans le navigateur, et se comportera toujours comme un bouton.
- `<div role="link">` sera restitué comme un lien par les lecteurs d'écran. Cependant, cet élément ne sera pas cliquable et ne ressemblera pas à un lien dans le navigateur.

L'attribut `role` permet également d'ajouter des sémantiques absentes de la spécification HTML. Par exemple : `role="tab"` pour un onglet.

## Les attributs `aria-*` (états et propriétés)

Les attributs `aria-*` servent à définir des états ou des propriétés sur certains éléments.

Par exemple :
- `aria-invalid` pour indiquer qu'un champ est en erreur.
- `aria-expanded` pour indiquer qu'un panneau est déplié.
- `aria-current` pour indiquer quel est l'item courant dans un menu.
- `aria-hidden` pour cacher un élément à un lecteur d'écran.
- `aria-required` pour les champs de formulaires qui sont obligatoires.
- `aria-describedby` pour les champs de formulaires à relier à une indication de format et/ou à un message d'erreur.

Également, on retrouve :

- `aria-label` & `aria-labelledby` pour donner des noms à certains éléments :
  - sur les balises `<a>` ou `<button>` SEULEMENT lorsque l'intitulé du lien ou du bouton n'est pas explicite (par exemple : "En savoir plus", "Lire la suite", etc.).
  - sur les balises `<input>` (ou autres champs de formulaire, comme `<textarea>`) SEULEMENT lorsque le `<label>` du champ n'est pas visible.
  - sur les balises `<svg>` informatives (ou seules dans un lien).
  - sur les balises `<figure>`, pour des raisons de compatibilité : reprendre le contenu de la balise `<figcaption>`.
  - sur des balises `<ul>` ou `<ol>` pour nommer des listes (ce n'est pas obligatoire).
  - sur les balises `<nav>` pour donner un nom à chaque menu.


## Les attributs `role` :

On distingue :
- Les attributs `role` pour les zones de la page pour des raisons de compatibilité :
  - ils sont redondants avec les balises HTML.  
  - exemple : (`role="banner"` avec le `<header>`).
- Les attributs `role` qui n'ont pas d'équivalent en HTML.
  - exemple : `role="tab"`. Il n'y a pas de balise `<tab>` en HTML.
- Les attributs `role` pour retirer la sémantique d'un élément.
  - exemple : `role="presentation"` ou `role="none"`.
  - exemple : à utiliser sur les tableaux de mise en forme.

Quelques exemples pour l'attribut `role` :
- `role="banner"` : à utiliser sur la balise `<header>` pour structurer l'en-tête de la page (pour rétrocompatibilité uniquement)
- `role="main"` : à utiliser sur la balise `<main>` pour structurer la zone de contenu principal (pour rétrocompatibilité uniquement)
- `role="contentinfo"` : à utiliser sur la balise `<footer>` pour structurer le pied de page (pour rétrocompatibilité uniquement)
- `role="navigation"` : à utiliser sur les balises `<nav>` pour structurer les menus (pour rétrocompatibilité uniquement)
- `role="img"` : à utiliser sur les balises `<svg>` pour indiquer aux lecteurs d'écran qu'il s'agit d'une image (informative)
- `role="figure"` à utiliser entre autres sur la balise `<figure>` dans les images légendées (rétro-compatibilité)
- `role="figure"` : à utiliser sur la balise `<figure>` dans les images légendées.
- `role="presentation"` : à utiliser sur les tableaux de présentation (ou de mise en forme), pour éviter que les lecteurs d'écran donnent des indications sur les numéros de lignes, de colonnes, etc.


## Les motifs de conception des composants d'interface riches

Pour certains composants interactifs, il est nécessaire aujourd'hui d'utiliser ARIA (la sémantique HTML n'est pas suffisante pour garantir une bonne restitution par les lecteurs d'écran).

Ces composants sont pour la plupart réalisés avec l'aide de Javascript. (Exemples : onglets, carrousels, panneaux dépliants, accordéons, modales...)

Pour ces composants, des ressources existent et précisent les interactions clavier attendues, ainsi que les attributs ARIA à utiliser. Ces "recettes" de composants se nomment des "motifs de conception" ("design patterns" en anglais).

Voir les fiches dédiées sur [AcceDe Web](https://www.accede-web.com/notices/interface-riche/) ou sur  [APG](https://www.w3.org/WAI/ARIA/apg/patterns/)

Il existe également de nombreuses librairies de composants web accessibles : 
- ex : [React-aria](https://react-spectrum.adobe.com/react-aria/index.html).
