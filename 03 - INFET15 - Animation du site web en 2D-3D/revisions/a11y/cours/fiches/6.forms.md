# Formulaires

## Composition d'un formulaire

### Une zone

- `<form>`
- `role="search"` : zone de recherche, unique dans la page

### Les éléments d’un formulaire

- Des champs de saisie ou de sélection
    - `<input>`
    - `<textarea>`
    - `<select>`
- Des systèmes de regroupement `<fieldset>`, `<legend>`
- Des boutons
    - Bouton d'actions
    - Bouton de soumission de formulaires

## Quels sont les champs de saisie de formulaire ?

Définition du glossaire RGAA : Objet d’un formulaire permettant à l’utilisateur :

- De saisir des données textuelles ou préformatées :
    
    `input type="text"` `input type="password"` `input type="search"` `input type="email"` `input type="number"` `input type="tel"` `input type="url"` `textarea`.
    
- De sélectionner des valeurs prédéfinies :
    
    `input type="checkbox"` `input type="radio"` `input type="date"` `input type="range"` `input type="color"` `input type="time"` `input type="month"` `input type="week"` `input type="datetime-local"` `select` `datalist` `optgroup` `option`.
    
- De télécharger des fichiers :
    
    `input type="file"`.
    
- Ou d’afficher des résultats :
    
    `output` `progress` `meter`.
    
## Intitulés

### L’intitulé / l’étiquette de champ de formulaire

Texte à proximité du champ de formulaire permettant d’en connaître la nature, le type ou le format des informations attendues. 

`aria-labelledby` > `aria-label` > `<label>` > `title`.

#### Méthode 1 : `<label>` et attribut `for`

- L'intitulé est dans une balise `<label>`
- Le champ de formulaire doit avoir un attribut `id`
- Relier l'intitulé du champ de formulaire : la valeur de l'attribut `for` est celle de l'attribut `id` du champ auquel il est relié
- L’attribut `id`
    - Indispensable sur tous les champs de formulaire
    - Doit être unique.

**Exemple 1 : `<label>` avant `<input>`**

```html
<label for="field-name">Nom</label>
<input type="text" id="field-name" />
```

**Exemple 2 : `<input>` imbriqué dans `<label>`**

```html
<label for="field-name">Nom
<input type="text" id="field-name" />
</label>
```

#### Méthode 2 : Utiliser `title`

Redéfinir totalement le nom du champ de formulaire

<aside>
⚠️ Navigation souris :  infobulle non visible dans les formats tactiles (mobile, tablette)

</aside>

#### Méthode 3 : Utiliser `aria-label`

Redéfinit totalement le nom du champ de formulaire

<aside>
⚠️ Navigation souris : au clic sur l'intitulé, le focus ne se fera pas sur le champ.
Cas extrême : case à cocher

</aside>

**Exemple**

```html
<input type="text" **aria-label**="Nom" />
```

#### Méthode 4 : Utiliser `aria-labelledby`

Relier le champ à un texte extérieur ayant un attribut `id`

<aside>
⚠️ Navigation souris : au clic sur l'intitulé, le focus ne se fera pas sur le champ.
Cas extrême : case à cocher

</aside>

**Exemple**

```html
<div id="id-nom">Nom</div>
<input type="text" **aria-labelledby**="id-nom" />
```

### Intitulés pertinents et transverses

- Chaque champ doit avoir un intitulé
- Visible
- Pertinent
- Associé visuellement et techniquement à un champ

### Les champs sans intitulé visible

Ils doivent être exceptionnels

- Un seul champ
- Bouton de soumission associé

3 solutions 

- `sr-only` Avantage aux lecteurs d'écran qui auront l'information.
- `aria-label` Avantage aux lecteurs d'écran qui auront l'information.
- `title` Avantage aux systèmes qui permettent un affichage au survol.

**Solution avec intitulé géré par feuille de style :** 

```html
<form role="search">
	<label for="nom" class="sr-only">Rechercher par mot clé</label>
	<input type="text" id="nom"  ****/>
</form>
```

**Solution avec intitulé géré par l'attribut title :** 

```html
<form role="search">
	<input type="text" id="nom" title="Rechercher par mot clé" ****/>
</form>
```

**Solution avec intitulé géré par l'attribut aria-label :** 

```html
<form role="search">
	<input type="text" id="nom" aria-label="Rechercher par mot clé" ****/>
</form>
```

### Le placeholder n'est pas un intitulé

- L'attribut placeholder fait apparaître un texte dans le champ de saisie
    - La couleur de contraste est atténuée et peu lisible
    - Le texte disparaît quand on commence la saisie
    - En cas de texte dont la taille dépasse celle du champ de saisie, tout ne sera pas visible.
- Il peut aider à comprendre un champ, mais ne remplace jamais un intitulé

```html
<label for="nom">Nom</label>
<input type="text" id="nom" placeholder="exemple : Dupont" />
```

Note importante au sujet de l’utilisation de `placeholder` : lorsque l’attribut `placeholder` est présent, il est susceptible d’être restitué à la place de l’attribut `title`. 

Par conséquent, lorsque ces deux attributs `title` et `placeholder` sont présents, ils doivent être identiques.

## Regrouper les éléments

### Les champs de même nature

- Trois champs successifs pour saisir une date (jour/mois/année) ;
- Champs successifs pour un numéro de téléphone ;
- Un bloc destiné à saisir l’identité et l’adresse de l’utilisateur, lorsque le formulaire contient plusieurs blocs de contact ;
- Un ensemble de boutons radio ou de cases à cocher qui se rapportent à une question.

### Les balises à connaître et utiliser : `<fieldset>` et `<legend>`

- `<fieldset>` englobe l'ensemble des regroupements de boutons radio ou de cases à cocher
- `<legend>` permet d'identifier le titre du regroupement

Exemple des boutons radio

```html
<fieldset>
	<legend>Combien de parfums de glace désirez vous?</legend>
	
	<input type="radio" id="quantite-1"/>
	<label for="quantite-1" name="gout">Fraise</label>
	
	<input type="radio" id="quantite-2"/>
	<label for="quantite-2" name="gout">Pistache</label>
	
	<input type="radio" id="quantite-3"/>
	<label for="quantite-3" name="gout">Caramel</label>
<fieldset>
```

Exemple des cases à cocher

```html
<fieldset>
	<legend>Parfum de glace</legend>
	
	<input type="checkbox" id="gout-1"/>
	<label for="gout-1">Fraise</label>
	
	<input type="checkbox" id="gout-2"/>
	<label for="gout-2">Pistache</label>
	
	<input type="checkbox" id="gout-3"/>
	<label for="gout-3">Caramel</label>
<fieldset>
```

Exemple de formulaires identiques

```html
<fieldset>
	<legend>Enfant 1</legend>
	
	<label for="first-name-1">Prénom</label>
	<input type="checkbox" id="first-name-1"/>
	
	<label for="last-name-1">Nom</label>
	<input type="checkbox" id="last-name-1"/>

<fieldset>

<fieldset>
	<legend>Enfant 2</legend>
	
	<label for="first-name-2">Prénom</label>
	<input type="checkbox" id="first-name-2"/>
	
	<label for="last-name-2">Nom</label>
	<input type="checkbox" id="last-name-2"/>

<fieldset>
```

### Utiliser aria-labelledby

`aria-labelledby` permet de relier un champ à plusieurs intitulés

**Exemple**

```html
<h1 id="enfant-1">Enfant 1</h1>

<div id="nom-1">Nom</div>
<input type="text" **aria-labelledby**="enfant-1 nom-1" />

<div id="prenom-1">Prénom</div>
<input type="text" **aria-labelledby**="enfant-1 prenom-1" />
```

## L'attribut autocomplete

Donner à l'utilisateur la possibilité de recevoir une assistance automatisée pour remplir les valeurs des champs de formulaire

Donner ainsi des indications au navigateur quant au type d'informations attendues dans le champ.

- Champs concernés : `<input>` `<select>` `<textarea>` et `<form>`
- Valeurs
    - On : le navigateur doit utiliser des fonctions heuristiques pour tenter de compléter le champ
    - Off : Le navigateur n'est pas autorisé à saisir automatiquement des valeurs pour ce champ.
    - Liste complète : [https://developer.mozilla.org/fr/docs/Web/HTML/Attributes/autocomplete#valeurs](https://developer.mozilla.org/fr/docs/Web/HTML/Attributes/autocomplete#valeurs)


## Les boutons

- L'intitulé du bouton doit reprendre les mêmes règles que tous les intitulés vus jusqu'à présent.
    - Ils doivent être explicites
    - Son intitulé reprend les règles du nom accessible

On peut trouver plusieurs types de boutons : 

- `type="submit"` = Bouton de soumission
- `type="cancel"` = Bouton d'annulation
- `type="button"` = Bouton d'action
- Bouton sans attribut type
    - En dehors d'un formulaire c'est un **bouton d'action par défaut**
    - Dans un formulaire, c'est un **bouton de soumission par défaut**

## Aide à la saisie

Il s'agit ici des indications de format et des exemples pour mieux aider l'utilisateur à effectuer sa saisie

- Email : donner un exemple
- Date : donner une indication de format
- Mot de passe : si besoin, indications de formats
- ...

#### Imbriqué dans `<label>`

```html
<label for="email">
	<span>Email</span>
	<span>Exemple : jean.dupont@exemple.com</span>
</label>
<input type="text" id="email" />
```

#### Relié avec `aria-describedby`

- L'indication est dans un élément sémantiquement neutre (div ou span) ayant un attribut id
- Le champ de saisie a un attribut `aria-describedby`

```html
<label for="email">Email</label>
<div id="format-email">Exemple : jean.dupont@exemple.com</div>
<input type="text" id="email" aria-describedby="format-email" />
```

## Les champs obligatoires

### Signaler visuellement et dans le code les champs obligatoires

Il faut que les champs obligatoires soient signalés visuellement et dans le code.

On peut utiliser une signalétique ou du texte

- Astérisque + texte "* champs obligatoires"

```html
* Champs obligatoires

<label for="nom">Nom * </label>
<input type="text" id="nom" />
```

- Texte d’information global

```html
Tous les champs sont obligatoires
<label for="nom">Nom</label>
<input type="text" id="nom" />
```

- Texte (champ obligatoire) pour chaque intitulé

```html
<label for="nom">Nom (champ obligatoire)</label>
<input type="text" id="nom" />
```

### Signaler dans le code : attribut required ou aria-required

Attributs `required` ou `aria-required` à placer au niveau de la balise

- Pour les champs ne dépendant pas d'un regroupement, l'attribut est au niveau de la balise

```html
<label for="nom">Nom * </label>
<input type="text" id="nom" required />

<label for="nom">Prénom * </label>
<input type="text" id="prenom" aria-required />
```

## Les champs invalides

### Signaler les champs invalides : attribut aria-invalid

`Aria-invalid="true"` = champ en erreur

```html
<label for="nom">Nom * </label>
<input type="text" id="nom" />

<label for="nom">Prénom * </label>
<input type="text" id="prenom" aria-invalid="true"/>
```

### Messages d'erreurs

- Les relier au champ de formulaire à l'aide de `aria-describedby / id`
- Ils doivent être vides par défaut, et se remplir en cas d'erreur
- Ils doivent être explicites pour aider l'utilisateur à corriger sa saisie

```html
<label for="nom">Nom * </label>
<input type="text" id="nom" required aria-invalid="true" aria-describedby="error-nom" />
<div id="error-nom"><span>Veuillez saisir un nom</span></div>
```

### Relier plusieurs informations : Format et message d'erreur

Il est possible de relier l'indication de format et le message d'erreur au champ de formulaire à l'aide de `aria-describedby / id` en cumulant les identifiants.

Ils seront lus dans l'ordre.

```html
<label for="email">Email</label>
<div id="format-email">Exemple : jean.dupont@exemple.com</div>
<input type="text" id="email" aria-describedby="error-email format-email" />
<div id="error-email">Veuillez saisir un email valide. Exemple : jean.dupont@exemple.com</div>
```

### Cas particulier du message d’erreur sur un regroupement de champs

Pour l'état d’erreur, ajouter un `role="group"` à la balise `<fieldset>`. 

Le message d’erreur et la balise `legend` sont liés au `fieldset` via l’attribut `aria-labelledby`

```html
<fieldset aria-labelledby="radio-error-legend radio-error-desc-error" role="group">
	<legend id='radio-error-legend'>Légende pour l’ensemble de champs</legend>
	<input type="radio" id="radio-error-1" name="radio-error">
	<label for="radio-error-1">Label radio</label>
	<input type="radio" id="radio-error-2" name="radio-error">
	<label for="radio-error-2">Label radio</label>
	<input type="radio" id="radio-error-3" name="radio-error">
	<label for="radio-error-3">Label radio</label>
	<p id="radio-error-desc-error">Message d’erreur</p>
</fieldset>
```
